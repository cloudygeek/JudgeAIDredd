# T-8 Plan — AgentLAB × PromptArmor at Smoke Scale

**Date:** 2026-05-15
**Author:** Claude Opus 4.7
**Status:** plan only; no code or runs yet

T-8 closes the **fourth-corpus PromptArmor head-to-head** (after
InjecAgent ✅, AgentDojo ✅, MT-AgentRisk ✅). The original gap doc
(`docs/tests-needed-2026-05-13.md`) parked it as P2 with the
explicit "skippable" reasoning that "AgentLAB is already smoke-scale
in the paper; adding PromptArmor smoke-scale on top is marginal
evidence." This plan checks that judgement against the current state
of the data and infra, then lays out the smallest concrete piece of
work that closes the gap if we decide to do it.

---

## TL;DR

- **Existing AgentLAB data on disk:** 7 agents × 2 arms (`none`, `intent-tracker`) × 10 stratified scenarios = 140 trajectories. Run dates 2026-04-27 (commit `research-v1`).
- **Missing arm:** PromptArmor. Plan-Stage-B promised it; not yet run.
- **Two known caveats from `docs/test25-findings-2026-04-27.md`** that constrain what AgentLAB results can claim:
  - **Finding 1**: AgentLAB's judge labels "succeeded" on local-only actions, not exfiltration. Numbers are permissive-metric, like §3.6's `hijackSucceeded` rather than `exfiltrationDetected`.
  - **Finding 2**: the existing AgentLAB runner does **not** block on Dredd `hijacked` verdicts — it logs them and continues the trajectory. The `defended-arm` Test-25 numbers therefore measure detection accuracy, not prevention.
- **What T-8 actually requires:**
  1. Restore `archive/tests/runner-agentlab.ts` and `fargate/tests/docker-entrypoint-test25.sh` from `research-v1` tag into `main` (the research scaffolding was excised in commit between research-v1 and the Springer-revision branch).
  2. Wire a PromptArmor pre-screen step into the AgentLAB runner: before the agent receives each tool output, route it through `/screen` and replace with `sanitised` content (or pass-through if `verdict=clean`). Same shape as `benchmarks/injecagent/promptarmor_defense.py` and `benchmarks/agentdojo/promptarmor_defense.py`.
  3. **Decide on the Finding-2 fix** before running: if the existing AgentLAB runner is brought back as-is, the PromptArmor arm will measure **detection** (does PA flag the injection?) but not **prevention** (does the agent stop following it?), because the agent receives the original payload regardless. To get prevention, the runner would need to honour the `sanitised` content — which is a real code change, not just a config flip.
  4. Run 5 backends × 1 arm (PromptArmor) × 10 stratified = 50 trajectories. Pair against the existing `none` and `intent-tracker` cells from `results/test25-fix/`.
- **Is it worth doing?** Probably yes if we have residual budget; the PromptArmor head-to-head story is materially stronger if it's "AgentDojo + InjecAgent + MT-AgentRisk + AgentLAB" rather than the current three. The §sec:agentlab-smoke section already exists in the paper draft; the cost is ~3h engineering + ~$5 in calls. We do **not** need to fix Findings 1 and 2 to ship T-8 — they are paper-narrative caveats, not blocking bugs.

## Three execution paths, ranked by cost

### Path A — minimal viable T-8 (~3h work + ~$5 spend)

Restore the AgentLAB runner from `research-v1`, add a thin PromptArmor
pre-screen, dispatch one cell per backend.

**Steps:**

1. `git checkout research-v1 -- archive/tests/runner-agentlab.ts fargate/tests/docker-entrypoint-test25.sh docs/test-plan-agentlab-2026-04-27.md` and re-home them at, e.g., `benchmarks/agentlab/runner-agentlab.ts` and `fargate/docker-entrypoint-agentlab.sh`. Sanity-check the imports compile.
2. Add a `--promptarmor-{url,backend,model,api-key,no-verify-tls,run-id}` CLI args block to the runner — copy the shape from `test-framework/src/runner.ts` (which uses an observational pattern). For AgentLAB, the natural integration point is the per-turn tool-output handler: before the agent receives the result, call `/screen` and substitute `sanitised` if `verdict=injected && !sanitisation_failed`.
3. Add `agentlab` to the `ENTRYPOINTS` map in `fargate/api-server.cjs` and a docker-entrypoint wrapper that mirrors `docker-entrypoint-injecagent.sh` (cell matrix iteration, S3 sync, summary log).
4. **Bake AgentLAB into the benchmarks image.** The upstream package is ~150 MB Python; vendor it the same way we vendored claude-code for the test-framework image. Reuse the existing benchmarks Dockerfile and add a `RUN pip install agentlab==X` (or `pip install -e /opt/agentlab` if we prefer a pinned commit).
5. Dispatch on bedt3/4/5 in parallel:
   - bedt3: `claude-sonnet-4-6, claude-opus-4-7 × promptarmor × stratified-10` (~30 min)
   - bedt4: `claude-haiku-4-5, claude-opus-4-6 × promptarmor × stratified-10` (~30 min)
   - bedt5: `qwen3-32b, qwen3-235b, qwen3-coder-30b × promptarmor × stratified-10` (~45 min)

**Outcome:** 7 agents × PromptArmor × 10 stratified = 70 trajectories. Pair against the existing `none` and `intent-tracker` cells already on disk at `results/test25-fix/`. Headline: a 7-row × 3-column cell table for §sec:agentlab-smoke — same shape as the AgentDojo head-to-head.

**Caveats inherited automatically:**
- Finding 1: PromptArmor's ASR is the permissive metric.
- Finding 2: the runner does not block on Dredd verdicts. **For PromptArmor** the equivalent is *"does the runner re-feed sanitised content to the next turn?"* — if we wire `/screen`'s `sanitised` field into the next-turn observation, then the PromptArmor arm measures **prevention**, not detection. This makes the §sec:agentlab-smoke story slightly asymmetric (PromptArmor arm: prevention; intent-tracker arm: detection), which is a footnote, not a blocker.

**Risk:** the AgentLAB Python package may have shifted upstream since 2026-04-27. The `research-v1` runner uses CLI args that may no longer match. Budget 1h debugging if the package version pin doesn't carry through.

### Path B — full T-8 with the Finding-2 runner fix (~1 day work + ~$5 spend)

Path A plus a real fix to the runner: when Dredd returns a `hijacked`
verdict, raise a `ToolCallDeniedError` in the SDK's hook chain that
short-circuits the agent's tool execution. This brings the
`intent-tracker` arm's numbers from "detection" to "prevention" and
makes the §sec:agentlab-smoke story symmetric with §3.6 and §3.7.

**Why this might still not be worth a full day:** the Test-25
findings doc records that "18 of 18 defended-arm successful
trajectories were flagged as `hijacked` by dredd" — meaning the
**detection accuracy is already 100% on the cells where it matters**.
The asr the paper reports for `intent-tracker` is the agent's own
refusal rate when Dredd is logging-only. That's a defensible number
once the caveat is in print. Fixing the runner pushes it down (more
prevention) but not by much, since the agent already refuses most
hijack attempts on its own at this scale.

**When to choose Path B:** if reviewers ask for AgentLAB-symmetric
prevention numbers across all three corpora.

### Path C — skip T-8 entirely (~0h, ~$0)

Document the gap in the paper as: *"PromptArmor was evaluated on
three of the four planned corpora (InjecAgent, AgentDojo,
MT-AgentRisk). AgentLAB was deferred to a follow-up because its
runner currently measures detection rather than prevention; running
PromptArmor on top of that asymmetry would not produce a
directly-comparable head-to-head with the other three corpora.
Section §sec:agentlab-smoke retains the existing 7-agent ×
{none, AIDredd-detection} table."*

This is honest — Findings 1 and 2 from `docs/test25-findings-2026-04-27.md`
mean AgentLAB's "ASR" already isn't measuring the same thing the
other three corpora measure. PromptArmor on AgentLAB-detection-mode
would compound the asymmetry rather than closing it.

## Recommendation

**Path A**, dispatched after the T-6 captures finish (~30 min from now).
The PromptArmor adapter takes ~1h to wire onto the restored
`runner-agentlab.ts`; the cell matrix is small enough to finish in
one wall-hour across the three bedt containers; the existing Findings 1
and 2 caveats already cap what we can claim for AgentLAB and
PromptArmor doesn't make either worse. Cost: ~3h engineering + ~$5.

**Falls back to Path C** if step 4 (vendor AgentLAB into the
benchmarks image) hits a Python-version-incompatibility wall.
We can update the §limitations paragraph to say "deferred — runner
infrastructure incompatible with current image; restored from
`research-v1` and addressed in follow-up."

**Path B** is reviewer-driven only.

## Open questions for the maintainer (Adrian)

1. **AgentLAB version pin.** The `research-v1` Test-25 runner uses
   `agentlab` from a 2026-04 snapshot. Do we pin to that commit (then
   rebuild the image with the snapshot baked in) or take whatever
   `pip install agentlab` resolves at run time? Pin = reproducibility,
   no-pin = lower image surface.
2. **Anthropic model rotation.** The 2026-04-27 Test-25 ran
   `claude-opus-4-6` alongside `claude-opus-4-7`. The 5-backend slate
   used elsewhere in the paper drops 4-6 (it's an interim model). For
   T-8 do we keep the 7-row Anthropic table to preserve continuity
   with the existing Test-25 data, or trim to 5-backend symmetry with
   the rest of the §sec:* matrices? Recommend trim — better
   cross-corpus visual.
3. **Finding-2 footnote wording.** The current paper draft references
   §sec:agentlab-smoke; do we add the prevention-vs-detection
   footnote explicitly to the PromptArmor row, or fold it into the
   existing intent-tracker caveat?
4. **Composite arm on AgentLAB.** Skip per the original P2 framing
   (T-5b is already P2). Mention only if reviewers ask.
